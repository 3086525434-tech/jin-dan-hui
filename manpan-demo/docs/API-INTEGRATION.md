# 业务数据与分析 Agent 接入约定（草案）

本文件供后续数据库／业务系统和分析 Agent 对接。以下路由是建议的同源网关约定，当前网站尚未部署这些接口，也没有接入真实数据库或在线模型。机器可读定义见 [integration-openapi.json](integration-openapi.json)。

本轮先保留脱敏工作簿和演示案件。接口批次可单独校验、预览；生产数据启用、真实案件生成、基线计算和业务权限须在正式接入时一起完成。当前演示引擎含固定历史日期与预设事实，不能直接替换日报后继续沿用这些结论。

当前前端准备同源 API 适配模块，运行配置默认关闭外部数据与 Agent 接入。健康检查和经校验的批次预览与现有演示工作区分开；分析请求的客户端约定已预留，演示聊天在数据来源与授权确认前不会切换到真实模型。这些准备不表示后端路由已存在。

## 路由与返回

所有接口返回 `application/json`。浏览器通过本站网关访问；网关再连接数据库／业务系统或模型服务。

| 路由 | 用途 | 成功返回 |
| --- | --- | --- |
| `GET /api/integrations/data/health` | 检查数据服务可达性 | `{ "ok": true, "service": "data" }` |
| `GET /api/integrations/agent/health` | 检查分析服务可达性 | `{ "ok": true, "service": "agent" }` |
| `GET /api/datasets/current` | 读取一个完整、获准展示的数据批次 | `schemaVersion`、`batch`、`daily` |
| `POST /api/analysis` | 对已授权批次提出问题 | `answer`、`sources`、`requestId` |

健康检查只说明接口可达，不表示数据已启用、权限检查全部通过或模型效果已验收。接口未配置、超时、拒绝访问、非 JSON 和校验不通过应分别显示；不能自动冒充已连接，也不应静默用演示回答替代真实接口失败。

## 数据批次

顶层字段固定为 `schemaVersion: "1.0"`、`batch` 和 `daily`，不夹带模型密钥、数据库地址或全量明细。

`batch` 必须包含：

- `id`：不可变批次标识，供分析引用。
- `source`：来源或版本引用，可回溯费用／点击与申请两端的来源；不含凭证。
- `generatedAt`：带时区的生成时间。
- `channel`：该批次唯一渠道范围。
- `start`、`end`：包含首尾的业务日期范围。
- `currency: "CNY"`、`grain: "channel_day"`、`applicationsScope: "all_channel"`。

`daily` 为 1–3660 行日报，每行只有以下字段：

| 字段 | 类型 | 口径 |
| --- | --- | --- |
| `event_day` | `YYYY-MM-DD` | 合法业务日期；同一批次不得重复 |
| `cost_yuan` | 有限非负数 | 该渠道 feed CPC 消耗，单位人民币元；不重复换算 |
| `click` | 非负安全整数 | 与消耗相同 feed CPC 范围的点击数 |
| `apply_cnt` | 非负安全整数 | APP 全渠道申请数；与 feed CPC 点击非同源 |

服务端和前端都应检查数值、日期、批次范围与重复日期，拒绝 `null`、数字字符串、`NaN`／无穷值或溢出值，不能把缺失值改为 0。`start <= end`；每行日期位于范围内，行按日期升序，首尾应与批次范围相符。缺少某日不能补造 0，应说明批次不完整。OpenAPI 的结构校验不能代替这些跨字段检查。

加权 CPC 为总消耗除以总点击；零点击时结果为缺失而非 0 或无穷值。申请除以点击仅是渠道 proxy，必须保留两端范围与非同源说明，不能改称单元或流量位转化率。本草案不提供对象日明细、快照回退、完整属性比对凭证或授信聚合，不能据此声称全部 M01 条件通过。

## 分析请求与证据

请求包含非空 `question`（最多 2000 字符）、`batchId`，以及可选 `caseId`。服务端按批次和调用者权限加载冻结证据；不能接受浏览器任意拼入的数值作为可信事实。未授权或不存在的批次、案件应拒绝。

响应 `answer` 为文字说明；`sources` 为非空引用列表，每项有 `label` 和可回溯的 `reference`；`requestId` 用于定位此次调用。前端按文本或安全 Markdown 显示，不执行响应中的 HTML、脚本、链接动作或投放指令。

Agent 只输出有引用的事实、最多三个主要假设、支持／反对证据、证据缺口和建议的核验步骤。缺证时明确补证，不确认故障，不虚构节省金额或提前发现天数。事实、假设、独立审查、业务决定、执行凭证和回访结果分别记录；接受建议不等于执行完成。Agent 不直接修改投放或案件业务状态，独立审查不由处置 Agent 自评替代。

当前最小响应只是问答读取约定，不代表已经完成 PRD M04／M05 的结构化输出、冻结版本、权限审查和生产验收；正式案件接口后续另定。真实批次与真实 Agent 返回不得写进现有 `DEMO-*` 示例案件。

## 访问边界

网站公开只表示页面可被拿到链接的人查看，不表示可以公开数据库、业务数据接口、模型调用或写入端点。正式启用前，由服务端确认访问身份、授权范围、可展示字段、脱敏要求和调用额度。前端隐藏按钮不构成权限控制。

数据库凭证与模型服务密钥只放服务端运行环境，不进入浏览器、源码、下载包或 URL。不要在聊天中发送密钥。公共演示里的新增记录仍是各自浏览器本地记录，不会自动同步为共享业务台账。

## 稍后需要的非敏感信息

1. 数据源类型、接口文档或脱敏返回样例，以及费用／点击／申请的字段映射、渠道范围、时区、刷新频率和完整日报判定方式。
2. 数据访问身份与允许展示给哪些访问者；数据库连接由哪个服务端网关承接。凭证随后通过运行环境设置。
3. 分析 Agent 的调用协议、请求／响应样例、是否流式、超时与错误格式、证据引用方式、可使用的数据范围；密钥随后通过运行环境设置。
4. 正式启用哪一批数据，以及演示案件与真实工作区的隔离和迁移规则。

这些信息确认后，再冻结接口版本、连接服务端数据源、完成端到端验证，最后切换真实工作区。
